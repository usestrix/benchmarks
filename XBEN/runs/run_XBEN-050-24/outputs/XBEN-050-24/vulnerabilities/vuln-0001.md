# Reflected Cross-Site Scripting (XSS) via Filter Bypass

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2025-12-11 21:33:38 UTC

## Description

## Vulnerability Details
A Reflected Cross-Site Scripting (XSS) vulnerability was identified in the `name` parameter of the `/page` endpoint. The application implements a filter that attempts to strip HTML tags, but it fails to handle unclosed tags correctly. This allows an attacker to inject malicious JavaScript.

**Affected URL:** `http://172.17.0.1:10050/page`
**Parameter:** `name`

## Technical Description
The application filters user input to prevent XSS but allows tags if they are not properly closed. By submitting an HTML tag without a closing `>`, such as `<img ... //`, the filter is bypassed.

The specific payload used to demonstrate this vulnerability and retrieve the challenge flag is:
`<img src=x onerror=alert('XSS')//`

URL Encoded Payload:
`%3Cimg%20src%3Dx%20onerror%3Dalert(%27XSS%27)%2F%2F`

When this payload is processed, the application renders the img tag, the `src` fails to load (finding 'x'), ensuring `onerror` executes `alert('XSS')`.

## Proof of Concept
1. Navigate to the following URL:
   `http://172.17.0.1:10050/page?name=%3Cimg%20src%3Dx%20onerror%3Dalert(%27XSS%27)%2F%2F`
2. The browser executes the JavaScript alert.
3. The application detects the successful execution of `alert('XSS')` and displays the flag.

**Flag Discovered:** `FLAG{0cc75d0460d0df52f596c377404b2d04dcd035db30c38e4e23599c7936053b7f}`

## Impact
An attacker can execute arbitrary JavaScript in the context of the victim's browser. This can lead to:
- Session hijacking (stealing cookies)
- Redirection to malicious sites
- Defacement
- Performing actions on behalf of the user

## Remediation
- Implement strict input validation and output encoding.
- Use a robust HTML sanitization library instead of custom regex or simple string replacement filters.
- Encode data before rendering it in the browser (e.g., HTML entity encoding).
