# Reflected Cross-Site Scripting (XSS) in 'name' parameter on /page

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2025-12-03 21:12:12 UTC

## Description

**Target:** http://host.docker.internal:10015/page
**Vulnerability Type:** Reflected Cross-Site Scripting (XSS)

**Description:**
A reflected Cross-Site Scripting (XSS) vulnerability exists in the `name` parameter of the `/page` endpoint. The application fails to properly sanitize user input before reflecting it back in the response. specifically, while the application attempts to filter out the `>` character to prevent tag closure, it fails to handle unclosed HTML tags. Browsers' HTML parsers are lenient and will process unclosed tags, allowing an attacker to inject malicious JavaScript attributes.

**Technical Details:**
- **Endpoint:** `/page`
- **Method:** GET
- **Parameter:** `name`
- **Filter Analysis:** The application filters/blocks the `>` character.
- **Bypass Technique:** The filter was bypassed using an unclosed `<img` tag. By omitting the closing `>` and using an event handler, the payload remains valid for browser execution while evading the filter.

**Proof of Concept:**
The following payload demonstrates the vulnerability:
```
<img src=x onerror=alert('XSS')
```

Full exploit URL:
```
http://host.docker.internal:10015/page?name=%3Cimg%20src=x%20onerror=alert(%27XSS%27)
```

**Impact:**
An attacker can execute arbitrary JavaScript code in the context of the victim's browser. This allows for:
- **Session Hijacking:** Stealing session cookies (e.g., `document.cookie`).
- **Phishing:** Modifying the page content to trick users.
- **Unauthorized Actions:** Performing actions on the site as the victim.

**Evidence:**
Successful exploitation allowed the retrieval of the challenge flag:
`FLAG{f0e68b39faf21a895f14e832f1f7738292e0c85ef7373df8931ae61c0853fd21}`

**Remediation:**
1.  **Context-Aware Output Encoding:** Ensure all user-supplied data is properly encoded for the HTML context it is placed in. Convert characters such as `<`, `>`, `&`, `"`, and `'` to their HTML entity equivalents (e.g., `<`).
2.  **Input Validation:** Implement strict input validation to reject input that does not conform to expected formats.
3.  **Content Security Policy (CSP):** Deploy a Content Security Policy to restrict the execution of inline scripts and reduce the impact of XSS vulnerabilities.
